# Agent Note：自适应验证器选择

Status: implemented

[English](2026-08-18-adaptive-verifier-selection.md) | 中文

## 问题

Best-of-N 选择此前执行一个固定验证计划并返回 tournament 最高分。即使前两名只有 0.500154 与 0.499846 这样的微小差异，系统仍会给出胜者，但该排序实际很不确定。始终提高评估次数或 criteria 虽能改善困难案例，却会让简单案例承担相同延迟与 token 开销。

选择策略必须把验证器排序解释与 Worker 执行分开。它可以对已完成轨迹增加评估工作，但不能启动 rollout、替换 Worker 客户端，也不能改变 Worker 模型、端点、并发、重试或预算。

## 决策

LLM-as-a-Verifier 提供商根据前两名分差报告相对选择置信度。结果包含最高分、次高分、分差、low／medium／high 等级，以及配置目标是否建议继续验证。Tournament 分数和置信度都是偏好信号，不是经过校准的任务正确概率。

自适应选择需要显式启用。其阶段是累积的 criterion／repetition 计划：每个后续阶段必须包含前一阶段的全部工作。启用后的默认计划依次在全部已配置 criteria 上执行 K=1、K=2 和 K=4，每个阶段后重新计算置信度，并在达到目标等级时停止。Pivots 保持固定。候选生成仍完全由现有 Harness 调用方负责。

提供商还提供需要显式启用的 `top-two` 策略。它先执行已配置的 K=1 PPT 基线，只在榜首两名分差低于配置阈值时比较这两个候选。每轮升级会调度两个候选方向，并通过同一 Bradley–Terry 与 PPT 分数总量把追加比较和已完成的 ring、pivot 结果一起聚合。低排名候选之间接近不会触发额外工作。

每次自适应选择拥有一个临时缓存标识。Python worker 将其映射到一个有界临时文件，其中的条目包含 phase、pair occurrence、候选索引、criterion 和 repetition。后续阶段只增加缺失的 criterion／repetition 比较，而同一个有向候选对在 ring 与 pivot phase 中被独立调度时仍保留为两次评估。TypeScript 提供商在 finally 路径释放缓存。缓存标识不含凭据，也不会在独立选择间共享。

Top-two 升级要求缓存中存在全部基线 ring 与 pivot 条目，并把追加工作记录在独立 `adaptive` phase。基线结果缺失属于内部错误；升级不会重新运行 tournament，也不会替换为平局。其调用上限以及操作级调用、comparison、延迟和 token 预算都是准入检查。升级被拒绝时返回有效基线排序和结构化预算原因。

原生 DeepSeek reasoning effort 是显式验证器请求设置。持久 Python 客户端在整个串行操作中应用一个不可变 effort，因此内部比较线程共享同一设置，不需要修改进程环境变量。基线与升级可以使用不同 effort。通用 OpenAI 兼容 transport 仍不发送 DeepSeek reasoning 字段。

提供商在上游细粒度评分和 PPT 原语周围负责一层小型选择编排。Ring 与 pivot 结果集在选择 pivots 时保持分离，最终聚合再让两者各贡献一次。缺少已调度结果属于内部错误；只有实际验证器失败才可以执行所配置的失败策略。这避免了 llm_verifier 0.2 无缓存路径中的 phase-B 映射替换问题：丢失的 ring 键会被读取为 0.5 平局，pivot 结果还可能代替 ring 结果。

启用自适应模式时，调用和耗时预算默认分别为 32 次与 45 秒。可选输入、输出和推理 token 限制使用验证器用量报告。在开始下一阶段前，提供商根据已完成工作单元估算新增成本，并拒绝预计会超过剩余预算的阶段。进行中的阶段不会被取消。置信度仍低于目标或后续失败开放阶段出错时，当前排序会连同结构化停止原因一起保留。

省略自适应配置时保留固定选择计划。提供商仍会报告置信度和验证遥测，但不会改变选中候选或原始候选对象身份。

## 考虑过的替代方案

- **把胜者分数视为置信度** — 拒绝，因为 tournament 分数用于候选排序，不是正确概率。
- **始终运行最大评估次数** — 拒绝，因为明显排序不应承担与模糊排序相同的验证成本。
- **低置信度阶段后重新生成候选** — 拒绝，因为 rollout 策略属于 Worker runtime，不属于验证器。
- **升级时重复所有早期比较** — 拒绝，因为带 phase 的缓存键会区分 pair occurrence、候选索引、criterion 和 repetition，同时不会合并独立的 ring 与 pivot 评估。
- **只用一个方向比较榜首两名** — 拒绝，因为这会重新引入提示词槽位偏差；定向升级始终调度两个方向。
- **在请求前后修改 `DEEPSEEK_EFFORT`** — 拒绝，因为验证器并发评分时修改进程全局环境不安全。
- **在准确预算边界中断进行中的阶段** — 推迟，因为持久 gateway 会串行执行操作，上游调用也不提供安全的部分阶段取消结果。
- **置信度仍低时不返回候选** — 推迟以保留现有调用方行为；低置信度与停止元数据会明确表达歧义。

## 后果

- 简单选择可以在第一个低成本阶段后停止，模糊选择则消耗额外的已配置验证器预算。
- 下游调用方可以区分选中胜者与该排序的确定程度，而不把两者视为任务正确概率。
- 预算在阶段边界执行，因此已完成阶段可能超过限制；发现该情况后不会再开始后续阶段。
- 选择范围缓存会在升级期间复用成功工作，保持独立 tournament phase 互不混淆，并在完成或失败后删除。
- Top-two 结果会分别报告基线与升级用量，以及第一阶段分差、触发或预算跳过、追加工作和胜者或排序是否变化。
- 自适应设置只影响固定 DSV4 Flash 验证器客户端。Worker 生成与编排保持不变。
